# GameHot 游戏情报深度研究 Agent

## 现状审查

现有 Ask 已经具备一套可继续演进的工程基础：`ask.run` 通过 pg-boss 执行；会话、消息、任务、事件与证据分别持久化；SSE 支持断线续传；十一个只读工具统一走公开读取层；引用只能指向本轮登记过的证据；模型和 Embedding 请求经过回执、预算熔断与未知结果保护。

检索、研究计划和引用检查已经接上。2026-10-22 在隔离库上用真实 DeepSeek 和正在运行的 `ask.run` Worker 跑过完整深度研究，记录见 [验收报告](ask-acceptance-2026-10-22.md)。同一 Gold 集的真实 Embedding 对照仍然没有跑。引用编号检查之外，深度模式会再判断结论是否被证据原文支持。

## 分阶段实施

### 第一阶段：可重复的评测基线（已完成）

功能范围：

- 严格 JSONL Gold 数据集，人工标注问题与相关公开文章。
- 复用生产 `search` 工具执行只读检索，计算 Hit Rate、Recall、Precision、MRR 与 P50/P95 延迟。
- 可选回放已完成回答，或通过 `taskId` 读取真实持久化任务，计算任务完成率、无降级完成率、引用合法性、人工标注主张的证据支持率、必要证据覆盖率、延迟与已知成本。
- 每次运行输出带数据集 SHA-256 指纹的 JSON 和 Markdown，供后续分支做同集对比。
- 评测器不调用 LLM，也不写业务数据。`keyword-v1` 不调用 Embedding；`hybrid-v1` 可能通过现有预算与回执调用配置好的 Embedding，并在报告中记录实际调用和已知成本。

验收标准：解析器拒绝未知字段与重复案例；指标有确定性单元测试；集成测试证明评测走真实 Ask 搜索路径；Typecheck 和 Ask 相关测试通过。

当前仓库同时保留格式示例和一份人工核对的真实数据基线：

- `modules/ask/evals/ask-gold.example.jsonl`：仅说明格式。
- `modules/ask/evals/ask-gold.2026-10-21.jsonl`：25 个检索案例，关联 2026-10-14 至 2026-10-21 的冻结公开快照。
- `modules/ask/evals/fixtures/gamehot-public-2026-10-21.json.gz`：1117 条公开资讯；只用于隔离测试数据库。

先把快照导入名称以 `_test` 或 `_ci` 结尾的数据库，再运行同集对比：

```bash
DATABASE_URL=postgres://127.0.0.1:5432/gamehot_eval_test npm run db:migrate
DATABASE_URL=postgres://127.0.0.1:5432/gamehot_eval_test npm run eval:ask:import -- modules/ask/evals/fixtures/gamehot-public-2026-10-21.json.gz
DATABASE_URL=postgres://127.0.0.1:5432/gamehot_eval_test npm run eval:ask -- --cases modules/ask/evals/ask-gold.2026-10-21.jsonl --engine keyword-v1
DATABASE_URL=postgres://127.0.0.1:5432/gamehot_eval_test npm run eval:ask -- --cases modules/ask/evals/ask-gold.2026-10-21.jsonl --engine hybrid-v1
```

导入脚本会拒绝非测试数据库。正式 Gold 必须由人核对文章后填写，不能用标题包含关系自动生成“正确答案”。当前基准、样本构成和验证边界见 [Ask 检索基准报告](evals/ask-retrieval-baseline-2026-10-21.md)。

回答指标有两种数据来源：案例内放 `replay` 可评测一份离线回放；放 `taskId` 则从 `ask_tasks`、`ask_evidence` 和对应回执读取真实状态、答案、延迟及成本。两者不能同时出现。成本按回执币种分别汇总，不跨币种相加。

### 第二阶段：Hybrid Search + Rerank（已完成）

Ask 的 `search` 工具已默认使用 `hybrid-v1`，其他公开读取调用继续默认使用 `keyword-v1`。实现严格复用公开可见性、精选范围、分类与时间条件，并冻结第一页的时间边界以保持分页一致。

当前边界：

- 关键词候选最多 60 条，时间范围内的语义候选池最多 300 条，融合后最多保留 120 条。
- 有当前模型且文本哈希有效的文章向量时，查询只生成一次 Embedding，并经过现有预算、回执及重用机制；不会在读请求中批量补算历史文章向量。
- 关键词排名与语义排名使用 Reciprocal Rank Fusion 合并；部分文章有向量时，其余文章使用有界字符 bigram 召回。
- Embedding 关闭、缺少有效文章向量或调用失败时，自动使用有界词法召回；具名游戏查询使用实体别名锚点，防止通用词把其他游戏混入结果。
- Hybrid 使用独立版本游标，游标绑定查询、范围和页大小；旧关键词游标与 Hybrid 游标不能混用。
- 当前没有引入 pgvector。候选池规模和 P95 证明需要数据库向量索引前，继续复用现有 `real[]` 存储。

验收标准：固定 Gold 集的 Recall 与 MRR 提升，P95 和单次成本在预算内；搜索范围、可见性与时间语义不退化；普通问答无需改用新界面。

真实快照上的当前结果是词法降级路径：相对 `keyword-v1`，Hit Rate 从 72.7% 提升到 100%，Recall 从 57.6% 提升到 88.6%，MRR 从 0.6742 提升到 0.9697；Precision 从 68.2% 降到 62.4%，P95 从 17 ms 增至 25 ms。外部 Embedding 调用为 0。向量路径已通过本地假 Embedding 服务的数据库集成测试，但因本地没有真实提供方凭据，尚未在同一 Gold 集上获得真实语义召回、延迟和成本数据。

第三阶段开始前又检查了一次：本机没有 `DATABASE_URL`，5432 端口没有 Postgres，Docker Desktop 引擎不在，环境里也没有 Embedding 凭据。因此没有重跑数据库集成测试，也没有重跑真实 Embedding 评测。上面的 Precision、P95 和零 Embedding 成本仍然是词法降级路径的已发布结果，Gold 数据集没有改动。

### 第三阶段：持久化 Plan & Execute 与深度研究界面（当前实现）

深度研究是独立的执行流程，不是把普通问答多跑几轮。普通模式仍走原来的循环，上限保持 6 次模型、8 次工具、180 秒。深度模式在领取任务前分流。研究动作的上限是 8 次模型、6 次工具、180 秒、最多 4 步、最多 1 次重规划。核验另有最多 2 次模型调用，见第四阶段。

执行方式：

- 两种模式的完整问候、致谢和能力介绍直接回答，不调用模型或工具；混合了新闻请求的句子不走此快捷路径。
- 深度规划器复用原有一次调用，先决定直接回答、澄清问题还是检索研究。一般概念和使用说明可直接回答；对象不明时先澄清。只有需要新闻证据时才输出带目标、工具和依赖的 JSON。直接回答决定写入检查点，恢复不重复付费。
- 易变事实（最新/当前动态、赛事结果、冠军、发布时间、版本更新、售价、排名等）即使规划模型误选直接回答，代码仍会转入有界站内检索；一般概念仍可直接回答。
- 研究计划解析失败时使用与问题对应的有界计划；默认只搜索问题本身，不再补一轮无关热点。明确选择直接回答但输出无效时，降级提示重试，不转成新闻检索。
- `search`、`get_latest`、`get_hot_topics`、`get_daily` 能从问题推导参数，直接调用，不再为这些步骤单独付费。
- `get_story`、`get_article`、`explain_hot`、`explain_selection` 必须先由模型给出资料里已经出现的 ID；没有真实 ID 就不调用。白名单外的工具名会被丢掉，不会执行。
- 一步没有新证据，且没有其他步骤仍在等待或执行时，才重规划一次。已完成步骤保留，新步骤使用新的序号。
- 有证据才做一次综合；综合必须引用本轮登记的证据。没有证据时直接说明检索不到，记为降级完成，不再调用模型。
- 计划、步骤、依赖、尝试、工具结果和检查点写入 `ask_tasks` 与 `ask_plan_steps`。同一轮的回执键不变，恢复时不重复计费。结果不明的回执会停止且不自动重试。回执仍为 pending 时不再次请求供应商，只放弃这一轮。取消发生在新的模型或工具调用之前；已经付费的那一轮会先取回结果。
- 队列重试等待 90 秒，长于 60 秒任务租约。`ask.run` 另有 30 秒心跳：进程失联后，由仍在运行的 pg-boss 监督在下一轮把作业判失败并进入重试，不必再干等 600 秒过期。600 秒仍是进程还活着但步骤卡住时的上限。研究墙钟只累计 Worker 实际持有任务的时间，排队空等不计入 180 秒。

前端在 `/ask` 提供普通研究和深度研究切换。切换保留未发送的输入，不发请求。深度模式有四条示例，点击只填入输入框。研究计划、当前步骤、工具调用和证据只来自 `research_plan`、`research_step` 以及原有的工具事件；没有百分比进度条。减少动态效果时关闭这些过渡。

研究阶段的回答仍然只能引用本次检索到的站内资料。普通模式会检查每个事实句都带本轮有效引用编号，并要求这句话能在被引证据的标题、摘要或正文摘录中逐字定位；改写到无法定位时，任务标记为降级。深度模式另要求事实表述逐字出现在该主张的引文中。普通句级匹配不等于独立判断现实真伪，深度模式也仍需要人工评测语义相关性判断。

验收情况：计划生成、重规划、取消、预算、回执恢复、重复 `clientRequestId` 和工具白名单有不依赖数据库的自动化测试。迁移 0068–0074 通过在线迁移安全检查。普通模式的上限没有改。隔离的 Postgres 17 上重跑过迁移、租约互斥、崩溃后续跑、取消、超时、回执重用和架构列检查。那些测试的模型是进程内函数或本机 HTTP 桩。真实模型和真实 pg-boss 的结果写在验收报告里。真实 Embedding 对照仍然没有跑。

### 第四阶段：Claim Verification 与游戏情报报告（当前实现）

综合草稿保存之后才进入核验。研究模型额度仍是 8 次；核验最多再调用 2 次，因此深度模式单次任务最多 10 次付费模型调用。直接工具和一次补检搜索不计模型次数。工具额度用完就跳过补检。核验额度不够时，不展示还没核过的草稿，只保留已登记证据。

核验规则：

- 模型提交主张、证据编号、逐字引文，以及相关性（relevant）、语义支持（entailed）和问题完成度（answered）判断。代码检查布尔字段与引文、数字、年份、来源规则；缺失语义字段不能通过。语义判断依赖模型，不能等同于独立事实证明。
- 引文必须完整出现在同一条对应证据的标题、摘录或来源名中。编号合法但原文对不上，记为证据不足。
- 结论里的每个数字都必须完整出现在这句引文里。同一篇材料别处有相同数字，不能拿来替这句结论背书。
- 写成官方确认、宣布或公布，但所引材料不是官方来源，记为存在争议。
- 两条主张的引文都核到，并且互相标为冲突，记为相互矛盾，两条都不进入核心结论。
- 把热度或同时发生写成原因，以及模型标明的推测，记为已移除。
- 第一次核验里，第一条证据不足的事实主张可以触发一次 `search` 补检。补检后再核验一次。新核验结果整体替换旧结果，不保留已被后续否定或改写的旧主张。
- 核验调用失败或返回无法解析的内容时，不编造主张，任务以降级报告结束。
- 主张、证据编号、引文和结论写入 `ask_claims`。崩溃后续跑同一核验轮次，不重复计费；第二次仍没有回执就停止。

报告按问题和已登记证据组织，不是把聊天回答写长：

- 核心结论只收录通过相关性、引文、数字、年份和来源检查的事实，并带证据编号，标为「来源支持」。事实表述必须能在对应引文中逐字定位；模型的 `entailed` 判断本身不能把未出现的改写提升为来源支持。问题里写了年份时，对不上的年份不能进入核心结论。「来源支持」仍不代表事实已经被独立证实。
- 时间线仅在问题要求时间或事件发展时展示；官方/媒体计数仅在问题涉及来源对比时展示。时间线、热度和核心引用使用受支持主张点名的资料，时间线按报道发布时间排序，不用文章标题代替结论。来源计数统计本轮检索材料，不当作答案完成度。
- 官方与媒体是来源类型的计数。来源类型只说明材料出处。
- 热度数字只从这些资料原文里的固定统计句提取。同一指标至少有两次记录才画柱状图。一次快照只列表，不画趋势。正文写明这些数字不能用来断言原因。
- 证据不足、有争议和互相矛盾的内容放在「尚未确认」或「差异与争议」，不进入时间线。明确无关或不被引文支持的主张及对应的未引用材料不在正文展开，完整执行记录仍保留。
- 研究任务需同时满足引用检查、至少一条受支持主张、所有提交主张通过检查、核心问题已回答，才记为完成。只有相关细节而未回答核心问题时记为降级完成；例如问谁夺冠，只查到比赛日期不算完成。

前端在深度回答上渲染这份结构：分节、时间线、来源计数、热度、可展开引用和核验状态。复制出去的是报告正文。图表、数字和引用都来自后端事件 `research_report`，单点数据不会被画成图。窄屏改为单列。减少动态效果时，报告区域的动画和过渡一并关闭。

人工主张案例放在 `modules/ask/evals/ask-claims.2026-10-21.jsonl`，不改检索 Gold。评测器不调用模型。离线回放里，带核验措辞的一组事实支持率为 1，旧式回答为 0，完成率都是 1，核验组的已知费用更低、耗时更高。这是同一批人工案例的回放对比，不是一次真实模型对打。

验收情况：不依赖数据库的测试覆盖了证据不支持结论、来源互相矛盾、官方表述配上媒体猜测、数字被改写、空检索、核验失败、核验预算用尽、取消未核验草稿，以及补检后只保留新的已证实结论。隔离数据库测试覆盖了主张落库、核验轮次恢复不重复计费，以及第二次恢复在新的付费调用前停止。浏览器自动化覆盖报告分节、引用展开、单点热度不绘图、复制正文、刷新后仍在、深色和 390 宽布局；那些请求使用桩。真实模型、真实 pg-boss 和真实页面上的报告见 [验收报告](ask-acceptance-2026-10-22.md)。真实 Embedding Gold 对照仍然没有跑。

## 技术选择

- 暂不引入 Multi-Agent 或 LangGraph。现有 pg-boss、任务表和事件流足以承载单 Agent 的计划与恢复，先用评测证明需要再增加复杂度。
- 暂不引入 pgvector。当前内容量和“限定时间窗口后召回”的模式适合复用 `real[]` 做有界相似度计算；数据量或 P95 超过目标后再评估索引扩展。
- 前端只展示后端已落地的能力。深度研究入口和过程视图与第三阶段的真实计划、步骤和工具事件一起上线。

## 自适应回答调整的验证边界

本次调整覆盖问候零调用、模型直接回答/澄清、检查点恢复、取消、无效直接回答拒绝检索、相关性与语义字段检查、答案完整性、前端自然回答和按需分节。测试中的模型响应为本机桩，真实 PostgreSQL 17 只用于隔离测试数据库；没有改动生产数据库或检索 Gold 集。

原有真实模型验收报告是历史版本的记录，不能代替这次新提示词的真实验收。本地未配置可用于本次验收的模型凭据，尚不能报告真实模型回答准确率、端到端延迟或费用改善；尤其语义核验仍可能误判，后续应在相同案例上验证真实模型的直接回答、模糊问题澄清、具体事实和复杂对比。

## 2026-10-26：研究数据工具

站内新增 `search_events`、`get_news_stats`、`get_attention_trend`，并扩展 `get_article(question)` 的公开正文定位和 `search(firstParty, source)` 筛选。它们共用 `publication/research.ts` 与原有公开性谓词，不直读未发布材料。

- 统计最多31天、20000条公开报道，SQL限时5秒；超过范围报错，不把前几条搜索结果当总量。事实按仍具证据关系的 fact 去重，独立来源复用本站通稿口径，采集完整性标为未知。
- 趋势只读取公开事件的完整小时观测，不输出内部热度分数；首个非零点归一为100，缺测保留null。超过72小时按24小时归并，有缺测的组不能生成观测值，最多约72个输出点。指数不代表玩家人数或因果关系。
- 历史统计保存参与的公开文章ID；来源撤回后按现有证据失效机制处理。趋势快照绑定公开事件。
- 深度模式规划与执行支持新工具，统计步骤以任务开始时间固定范围，显式日期使用北京时间；开销和步骤上限沿用原策略。
- 外部 MCP 新增 `get_article`、`search_news`、`search_events`、`get_news_stats`、`get_attention_trend`。旧 `search` 保持兼容，新增 `search_news` 提供来源/日期筛选，且外部接口强制使用免费关键词检索，不触发Embedding或模型。对应只读 Agent REST 路径为 `/article`、`/search-news`、`/search-events`、`/news-stats`、`/attention-trend`，统一位于 `/api/v1/agent` 下。
