# GameHot 游戏情报深度研究 Agent

## 现状审查

现有 Ask 已经具备一套可继续演进的工程基础：`ask.run` 通过 pg-boss 执行；会话、消息、任务、事件与证据分别持久化；SSE 支持断线续传；八个只读工具统一走公开读取层；引用只能指向本轮登记过的证据；模型和 Embedding 请求经过回执、预算熔断与未知结果保护。

当前主要缺口是：检索仍是关键词与实体别名匹配；文章 Embedding 只用于事件归组，没有服务 Ask；Agent 没有显式研究计划和可恢复步骤；引用检查只能发现伪造编号或裸链接，不能判断结论是否真的被证据支持；也没有固定数据集衡量一次改动对检索、引用、延迟和成本的影响。

## 分阶段实施

### 第一阶段：可重复的评测基线

功能范围：

- 严格 JSONL Gold 数据集，人工标注问题与相关公开文章。
- 复用生产 `search` 工具执行只读检索，计算 Hit Rate、Recall、Precision、MRR 与 P50/P95 延迟。
- 可选回放已完成回答，或通过 `taskId` 读取真实持久化任务，计算任务完成率、无降级完成率、引用合法性、人工标注主张的证据支持率、必要证据覆盖率、延迟与已知成本。
- 每次运行输出带数据集 SHA-256 指纹的 JSON 和 Markdown，供后续分支做同集对比。
- 评测器不调用 LLM 或 Embedding，不产生模型费用，也不写业务数据。

验收标准：解析器拒绝未知字段与重复案例；指标有确定性单元测试；集成测试证明评测走真实 Ask 搜索路径；Typecheck 和 Ask 相关测试通过。

运行：

```bash
npm run eval:ask -- --cases modules/ask/evals/ask-gold.jsonl --split development
```

示例文件 `modules/ask/evals/ask-gold.example.jsonl` 只说明格式。正式 Gold 必须由人核对文章后填写，不能用标题包含关系自动生成“正确答案”。

回答指标有两种数据来源：案例内放 `replay` 可评测一份离线回放；放 `taskId` 则从 `ask_tasks`、`ask_evidence` 和对应回执读取真实状态、答案、延迟及成本。两者不能同时出现。成本按回执币种分别汇总，不跨币种相加。

### 第二阶段：Hybrid Search + Rerank

在公开可见、时间范围受限的候选池中并行取得关键词结果与语义结果，使用可解释的融合分数重排。优先复用现有 Embedding 服务和 `real[]` 存储；在数据规模证明需要前不引入 pgvector。Embedding 不可用、预算触发或超时时自动退回关键词路径。

验收标准：固定 Gold 集的 Recall 与 MRR 提升，P95 和单次成本在预算内；搜索范围、可见性与时间语义不退化；普通问答无需改用新界面。

### 第三阶段：持久化 Plan & Execute 与深度研究界面

为任务增加 `normal` / `deep` 模式及版本化研究计划。深度任务把步骤、依赖、尝试、工具结果和检查点持久化，并允许 worker 在安全边界内续跑。前端此时才上线模式切换、两套示例问题和研究过程视图；每一条进度都来自后端事件，不使用定时假进度。切换模式保留输入，不触发模型。

验收标准：复杂问题可生成、调整并完成多步计划；进程中断后从已提交检查点恢复；普通模式行为与成本不变；移动端、深色模式、减少动态效果和键盘操作通过浏览器检查。

### 第四阶段：Claim Verification 与游戏情报报告

把最终草稿拆成事实主张，建立主张到证据的映射；证据不足时定向补检一次，仍不足则降级措辞或删除结论。报告复用现有故事、报道时间线、来源类型和热度历史，生成事件时间线、报道差异、趋势解释与引用清单。

验收标准：人工 Gold 集上的事实支持率与引用覆盖率达到门槛；官方消息、媒体报道和未证实信息不会混写；报告中的趋势数字可追溯到查询与时间窗口；补检次数和成本有硬上限。

## 技术选择

- 暂不引入 Multi-Agent 或 LangGraph。现有 pg-boss、任务表和事件流足以承载单 Agent 的计划与恢复，先用评测证明需要再增加复杂度。
- 暂不引入 pgvector。当前内容量和“限定时间窗口后召回”的模式适合复用 `real[]` 做有界相似度计算；数据量或 P95 超过目标后再评估索引扩展。
- 前端只展示后端已落地的能力。第一阶段没有用户可见的“深度研究”入口，避免出现只有动画的空壳。
