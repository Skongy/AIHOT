## 审查范围与总体判断

- 采集：RSS、JSON/网页读取、详情补抓、统一材料入库、修订与时间归档、抓取游标、队列交接。
- AI：预筛、独立评分、写作、Embedding、付费回执、预算与失败恢复。
- 事件与热度：候选召回、聚簇、合并、摘要、来源去重、时间衰减、热点快照。
- 数据与出口：公开读取层、来源撤回、日报编排、API、MCP、后台认证、出站 SSRF/TLS 防护。
- 调度与模块：pg-boss 定时任务、恢复与保留策略，问答任务与游戏异动采集。

现有公开读取层、付费回执、预算熔断、材料修订与统一时间规则值得保留。没有证据支持重写架构或调整新闻评分、热度权重。本轮未调整这些规则，也没有修改页面样式。

## 已处理的问题

| 级别 | 问题及证据 | 修复与主要位置 |
| --- | --- | --- |
| 高 | 同一问答请求并发重试时，唯一约束冲突返回 500；原补偿逻辑还可能将另一请求成功创建的任务标为失败。8 次同 ID 并发测试修复前有 7 次返回 500。 | 对会话行加事务锁，在事务内复查幂等键和执行中任务。消息、任务和队列继续原子提交；删除过时补偿函数及其测试，增加真实队列失败回滚测试。`modules/ask/src/http/routes.ts`、`db/store.ts`。 |
| 中 | HTTP 参数被 TypeScript 类型断言当作字符串，数字/对象调用 `.trim()` 抛异常，错误请求返回 500。 | 在 `modules/ask/src/http/decide.ts` 做运行时类型检查，统一返回 400；非法请求不写任务。 |
| 中 | A→B 与 B→A 事件合并分别先锁不同记录，随后等待对方。真实 PostgreSQL 并发测试复现死锁。 | `packages/backend/src/events/merge.ts` 按 ID 顺序锁定双方，再复查合并状态；并发测试确认只有一个合并成功且无别名环。 |
| 中 | Steam 的 Retry-After 仅从最近 15 分钟的三条请求读取，长等待或并发新记录能掩盖限流；连续缺失历史的 404 又会错误阻断整个主机。 | `modules/radar/backend/steam.ts` 独立检查未到期的主机限流；404 与服务端/传输失败分离；复用已有 Retry-After 解析并限制异常大值。三个上游替身用例覆盖拒绝、恢复和缺失历史。 |
| 中 | 游戏异动原因已保存，但模型回执停留在 received，业务状态和费用审计状态不一致。 | `modules/radar/backend/collect.ts` 在同一事务保存原因、证据并完成回执。假模型测试确认完成状态且重复扫描不再次付费。 |
| 性能 | 月度异动逐事件核验新闻来源，最多 300 条事件可产生 300 次权限查询。 | `packages/backend/src/publication/radar.ts` 汇总、去重引用 ID 后只查询一次。仍按当前权限过滤，并在任何证据被撤回/尚未发布时隐藏原分析。新增混合引用测试。仅确认查询次数减少，未声称生产 P95 收益。 |
| 测试 | 测试数据库名只依赖 PID；Windows 复用 PID 后，同一轮出现多次 database already exists。 | `tests/databases.ts` 在副本名中加入文件名摘要，清理兼容旧命名。最终广泛回归未再次出现重名。 |
| 安全 | npm 官方生产依赖审计报告 7 个受影响包，其中 3 个 high。涉及内存耗尽、TLS/请求处理、HTML 清洗等公告；不等于每项都已证明可利用本站。 | 仅更新现有依赖的兼容修复版并刷新锁文件，未使用强制升级或新增框架。复查生产依赖公告为 0。 |
