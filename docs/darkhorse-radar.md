# 游戏异动运行说明

入口 `/radar`；只读月度接口 `/api/radar/month?month=2026-10`。沿用已确认的A2设计。月份和日期使用Asia/Shanghai；原始时间UTC。所有公开结果经 `publication/radar.ts` 投影；打开页面不发采集或模型请求。

## 数据与口径

- 实时：Steam当前Top100和最多100款榜外候选，榜单每15分钟；榜外每次最多50款轮转。候选来自第三方公开目录/movers、明确Steam原文链接、新入榜游戏。没有全Steam覆盖承诺。
- 历史：SteamData公开JSON API，`/api/apps/{appid}/history?range=30d`小时记录。公开目录本次500款；历史源覆盖有限，也不是官方历史接口。原始响应可由显式回填命令读取缓存，保留采集来源及获取时间；事件保留规则、基线日摘要、样本摘要校验值及发现日真实曲线。
- “当天最高在线记录”是本地日有效定时记录的最大值，不是精确日峰值、销量或DAU。缺测不补零；接口错误和无效appid不能保存为零。
- 先前七个日历日中至少三天且每日十二个小时才计算基线；使用可用日峰值中位数。七天齐全、此前低于5000、至少五倍且增加2000，并有跨两小时三次增长记录，才规则确认。其余达到初始增长门槛者标为疑似，较高既有基线标为翻红。新大作/明确大型发行商保守排除。参数尚未标注评测校准。
- 缺历史时允许同日冷启动观察：必须先有三个低于1000的小时记录，再有跨两小时三次至少5000的记录；仅标为疑似。开始监控时已经热门的游戏不能当作突然增长。
- 历史事件的event_day为回溯识别日期，detected_at为系统实际归档时间。不会伪造10月初已经运行监控。持续增长14天内去重，不每天重复发现。
- 模型只整理仍公开的本站报道和Steam官方公告背景，经已有receipt和预算执行。不以人数曲线推断“主播带火”。无证据时显示原因未知，公告背景也不等于因果。来源撤回时公开读取隐藏对应总结。

## 调度、安全和恢复

`radar.collect`复用pg-boss；live每15分钟、catalog每天03:05、warmup每小时08/38分、explain每小时12/42分。遵循已有COLLECT_ENABLED和MODEL_CALLS_ENABLED；不开新独立总开关。每任务两次重试、间隔300秒；daily HTTP预算8000包含回填和重试，存PostgreSQL。429遵循Retry-After，主机连续错误冷却15分钟。

运行记录在job_runs，逐次HTTP状态/错误/冷却在radar_requests。页面展示最近成功采集时间，过45分钟显示待更新；超过1小时形成既有运维发现。不得把有历史内容当作采集健康证明。

Steam出网沿用guardedFetch；在现有EGRESS_PROXY_HOSTS追加 `api.steampowered.com,store.steampowered.com,api.steamdata.dev`，必要时追加官方图片实际域名。保留原有名单及所有代理凭据，禁止关闭SSRF检查或开放代理公网端口。API提供方失败不会切换成爬取SteamDB。

新增表仅属于模块，逐文件在线DDL；不修改新闻表。原始样本保留35天、请求14天，日汇总和事件档案保留。删除原始样本不删除事件内保存的曲线及基线依据。

## 显式回填

部署迁移完成后，在包含既有后端配置的容器中运行：

```sh
node modules/radar/scripts/backfill.ts --limit=500 --explain
# 可选：读取本轮已保存的公开响应；不需要重新请求500份历史
node modules/radar/scripts/backfill.ts --cache=/data/radar-history-20261026 --limit=500 --explain
```

每游戏独立提交和history_loaded_at检查点；失败时输出appid/错误，退出码1，重跑只处理未完成游戏。元数据失败发生在历史完成检查点前，因此能重试；样本和事件唯一键防重复。不自动在setup/迁移中大批回填。缓存目录必须是可信的运维输入，不接受公开上传。首次全部回填后可重跑验证幂等，再手工触发一次live检查，并检查计划任务随后实际运行。

## 验证

`modules/radar/tests`包含纯规则及数据库集成；`apps/web/tests/radar.test.ts`覆盖双主题四宽度、月份切换不跳底、日期定位、右侧详情、真实时间曲线、缺图降级与空月份。数据库测试必须使用*_test或*_ci隔离库；禁止向生产库执行测试清理。
