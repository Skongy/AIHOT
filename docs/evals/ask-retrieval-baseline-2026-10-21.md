# GameHot Ask 检索基准报告（2026-10-21）

## 结论

在同一份真实公开资讯快照和同一组人工核对问题上，新的有界 Hybrid 检索词法降级路径提高了召回和首条相关结果排名，但牺牲了部分精确率并增加了少量延迟。当前结果支持把 Hybrid 接到 Ask 的 `search` 工具，同时也说明还需要使用真实 Embedding 提供方做一次同集验证，才能判断向量召回的实际收益、延迟和费用。

| 指标 | `keyword-v1` | `hybrid-v1`（词法降级） | 变化 |
| --- | ---: | ---: | ---: |
| Hit Rate | 72.7% | 100.0% | +27.3 个百分点 |
| Recall | 57.6% | 88.6% | +31.0 个百分点 |
| Precision | 68.2% | 62.4% | -5.8 个百分点 |
| MRR | 0.6742 | 0.9697 | +0.2955 |
| P50 延迟 | 9 ms | 16 ms | +7 ms |
| P95 延迟 | 17 ms | 25 ms | +8 ms |
| 负例空结果准确率 | 100% | 100% | 持平 |
| 外部 Embedding 调用 | 0 | 0 | 持平 |
| 已知模型成本 | 0 | 0 | 词法路径无模型费用 |

提交前在同一隔离数据库立即复跑一次，质量指标完全一致；P50 为 10 ms / 19 ms，P95 为 19 ms / 30 ms。单机毫秒级延迟会受缓存和当时负载影响，因此当前可观测增量是 P95 约 8–11 ms，而不是稳定的生产 SLA。

## 数据与方法

- 数据源：GameHot 公开 API 的只读快照，没有读取或修改生产数据库。
- 快照范围：2026-10-14 至 2026-10-21，共 1117 条公开资讯。
- Gold 集：25 个案例，其中 22 个正例、3 个无结果负例。
- 数据集 SHA-256：`3a2728450d22a89186764c29856a74830f1b52f332e44450760f348113e42969`。
- 比较方式：将快照导入隔离的 `gamehot_eval_test` 数据库，分别运行 `keyword-v1` 和 `hybrid-v1`；两次运行使用相同查询、过滤条件、结果上限和人工相关项。
- 统计方式：正例计算宏平均 Hit Rate、Recall、Precision 和 MRR；负例单独计算空结果准确率，避免空 Gold 扭曲正例指标；延迟包含数据库检索与本地重排。

Gold 集覆盖具名事实、英文别名、语义改写、重复报道、官方版本更新、赛事、研究数据、跨分类、冲突报道和无结果控制。4 个 development 案例用于实现期检查，21 个 evaluation 案例用于保留集观察。数据来自一周窗口，因此能代表当前高频问答形态，但不能代表长期历史查询、极低频游戏或所有语言；后续应按时间追加冻结批次，不能修改本批 Gold 来美化结果。

## 实现边界

Hybrid 检索沿用现有公开读取层的权限、精选范围、分类和时间条件。每次搜索最多读取 60 条关键词候选和时间范围内最新的 300 条语义候选，使用 Reciprocal Rank Fusion 合并，最多保留 120 条供稳定分页。

若候选文章存在当前模型且文本哈希有效的向量，查询 Embedding 只调用一次，并经过现有预算与回执。若服务关闭、没有有效文章向量或调用失败，则使用有界字符 bigram 召回；识别到具名游戏时，候选还必须命中该实体的名称或别名，以避免通用的“版本”“更新”等词召回其他游戏。

本次真实快照不携带文章向量，本机也没有真实 Embedding 凭据，所以 25 个案例全部记录为 `hybrid-lexical-v1` 和 `embeddings_unavailable`。向量路径通过了本地假 Embedding HTTP 服务和真实 PostgreSQL 的集成测试，覆盖有效向量读取、查询回执、融合排序、游标分页和相同查询回执重用；这只能证明工程路径可运行，不能替代真实模型效果与费用评测。

## 退化与风险

- Precision 下降 5.8 个百分点，说明词法扩召回带入了更多非 Gold 结果。Ask 工具默认只取较小页，MRR 的提升能优先给模型相关证据，但长列表仍可能增加阅读噪声。
- P95 增加 8 ms，来自额外候选读取和进程内重排。当前绝对值较小，但生产数据库数据量、并发和远程网络会改变结果。
- 语义候选只覆盖指定时间范围内最新 300 条；超大时间窗口中的较旧相关文章可能仍依赖关键词命中。这是控制延迟和内存的明确取舍。
- 部分向量覆盖会形成向量与词法混合排名。真实提供方验证前，`0.3` 的向量相似度阈值只是保守工程默认值，尚未针对 Gold 集校准。
- 当前基准只评测检索，不包含模型最终答案质量。回答完成率、引用准确性和主张支持率要等有人工核对的回答回放或持久化任务样本后单独报告。

## 复现

```bash
DATABASE_URL=postgres://127.0.0.1:5432/gamehot_eval_test npm run db:migrate
DATABASE_URL=postgres://127.0.0.1:5432/gamehot_eval_test npm run eval:ask:import -- modules/ask/evals/fixtures/gamehot-public-2026-10-21.json.gz
DATABASE_URL=postgres://127.0.0.1:5432/gamehot_eval_test npm run eval:ask -- --cases modules/ask/evals/ask-gold.2026-10-21.jsonl --engine keyword-v1
DATABASE_URL=postgres://127.0.0.1:5432/gamehot_eval_test npm run eval:ask -- --cases modules/ask/evals/ask-gold.2026-10-21.jsonl --engine hybrid-v1
```

评测结果默认写入被忽略的 `.data/evals/ask/`，避免把带运行时间和逐案例结果的临时产物提交到仓库。仓库提交 Gold、冻结快照、导入脚本和本报告，保证后续分支可以用同一数据重跑。
