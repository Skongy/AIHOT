# 后台访问记录

入口：`/admin/visits`，沿用后台会话认证，接口 `/api/admin/visits` 禁止匿名读取且不允许缓存。

页面在浏览器完成加载、站内路径切换时上报 `/api/site/visit`。不统计预加载、查询参数变化、静态资源、API 和后台访问；没有 JavaScript、上报被拦截或限流时会漏记。这是浏览记录，不是服务器完整访问日志，不提供在线人数或身份识别。来源仅保留站点 origin，路径去除查询参数和 fragment，不收集 Cookie、问答正文、地理位置或设备指纹。

原始 IP、服务端接收时间、页面路径、来源站点及 User-Agent 存在 `site_visits`。时间筛选按北京时间自然日，默认当天；同一 IP 可能对应多人，浏览器信息和路径来自客户端，不能作为安全审计证据。原始记录在现有每日清理任务中删除超过 30 天的数据。页面按时间倒序，每页 50 条，可精确筛选 IPv4/IPv6。

## 上线前检查

- 执行新增数据库迁移（0060–0062），沿用现有迁移检查和发布流程。
- `SITE_URL` 必须与浏览器访问的 origin 一致；跨 origin 上报拒绝。每个 API 进程每分钟至多 600 条，每 IP 至多 60 条，同时写入至多 10 个；限流返回 429，不重试、不影响阅读。
- API 仅供内部网络访问；公网只暴露 web/反向代理。沿用现有可信代理部署方式：外层代理覆盖或追加实际客户端地址，web 配置 `TRUST_PROXY=true` 且只接受可信代理连接。使用 X-Forwarded-For 最右侧地址，忽略客户端伪造的左侧值；无转发头时使用 socket 地址。不要直接将内部 API 端口暴露公网。
- 管理员需核对现行隐私说明是否涵盖上述收集与保留范围。本次没有擅自修改站点隐私条款。
- 本功能启用后才开始记录，不会从现有数据伪造历史访问。
