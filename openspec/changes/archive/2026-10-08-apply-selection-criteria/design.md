# Design：apply-selection-criteria

## Context

当前流水线（`docs/selection.md`）：采集 → 预筛 `prefilter.md`（PASS/BLOCK/UNKNOWN）→ 两次独立评分 `selection-score.md`（0–100，和 ≥ 2×门槛）+ 结构化 `structure.md`（类别、标签、事实）→ 写作（入选和接近入选用 `understand.md` = `content-understanding.md` + 规则；其余用 `summarize-*.md`）→ 归组去重 `group-*.md` → 精选。日报由 `reports/edition.ts` 按规则编排，**不调用模型**；周报月报只让模型写总述（`report-period*.md`）。

门槛在 `industry/selection.ts`（T1 60 / T1_5 65 / T2 76 / understandFloor 50），是 AIHOT 在 AI 领域的数，**没有在游戏样本上校准过**。

灵感给的标准（含晚到修订）：
- 精选 = 会改变玩家玩不玩、买不买、等不等的消息；「一手出处 / 有新信息 / 国内相关」**满足任意一条即可**（不是三者都要）。官方源用于验证，并优先作为标题外链。
- 产品焦点：Steam 游戏；种子主题为以撒的结合：重生、杀戮尖塔 2、喵喵的结合、博德之门 3。
- 排除：攻略、抽卡、软文、无源爆料（有可信出处的传闻可以，但要标“传闻”）、搬运、标题党、八卦、折扣、账号交易。
- 行业纳入：大版本更新、新赛季、DLC、国服停服或回归、影响平衡的大改、版号和监管政策、大厂财报/并购/裁员、首发评分汇总、有分量的深度评论。行业排除：例行维护、只修 bug 的小补丁、单个皮肤或卡池上新（除非炸了 → 热点）、小厂融资通稿、披着评测外衣的营销稿。
- AI 日报：一句话头条；3 条要闻；分类速览 新游 2–4、电竞 2–4、行业 3–5；1–2 条社区争议；明日关注；每条注明来源。

## Goals / Non-Goals

**Goals**：把以上标准写进提示词；用标注样本定门槛；日报结构按灵感改（社区争议除外）。
**Non-Goals**：不改五轴结构和类型权重；不改热点；不改周报月报。

## Decisions

### D0. Steam 焦点与种子主题

主题页 `company` 组只保留四款 Steam 游戏；手游/端游 F2P 官源停用；为四款游戏各接一条 `store.steampowered.com/feeds/news/app/{appid}/` RSS。媒体与平台源（含 PS/Xbox/任天堂、HLTV）暂留。提示词读者画像改为国内 Steam 玩家。

### D1. 改“例子和上限”，不改评分结构

遵守上游 AGENTS.md：“改评分标准时保留原有结构（内容类型、五个维度加权、噪声压制、安全边界），替换的是‘什么算重要’‘什么算噪声’的例子。”排除项全部写成对某一轴的**上限**（如 `sig ≤ 2`），这样两次评分仍是一个整数分，门槛机制不变。

### D2. 排除项落在哪一步

| 排除项 | 预筛（BLOCK = 全站不可见） | 评分（压分 = 不进精选，仍在全部） |
|---|---|---|
| 攻略、抽卡建议、配队 | 否 | `sig ≤ 2`，`reson ≤ 4` |
| 软文、营销稿（含伪评测） | 否 | `cred ≤ 2`，`sig ≤ 2` |
| 无源爆料 | 否 | `cred ≤ 2`，最终分 ≤ 40；有可信出处的传闻 `cred ≤ 5` 并标“传闻：” |
| 搬运（无增量转载） | 否 | `nov ≤ 2`；归组时“没有新信息”本就不进精选 |
| 标题党 | 否 | 标题与正文不符 → 最终分 ≤ 30（已有） |
| 八卦 | 否 | `sig ≤ 1` |
| 折扣、史低、促销 | 否 | `sig ≤ 2`，`act` 不加分 |
| 账号交易、代充、外挂、礼包码 | **是**（Q3-2，建议） | — |
| 例行维护、只修 bug 的补丁 | 否 | `sig ≤ 2` |
| 单个皮肤、单个卡池上新 | 否 | `sig ≤ 3`，`reson ≤ 5`（炸了靠热点） |
| 小厂融资通稿 | 否 | `sig ≤ 3`，`cred ≤ 4` |

只有“账号交易/代充/外挂/礼包码”这种纯广告进预筛 BLOCK，其余都留在“全部”里，只是不进精选，避免误杀。

### D3. 国内相关性写进 `reson`，一手出处写进 `cred`

- `reson`：国服/国区可玩、国内上线或停服、国内赛事战队、国内厂商与政策 → 正常；只在海外发生、无国服且国内玩家难以接触 → `reson ≤ 4`。
- `cred`：官方公告、厂商财报、监管公告、赛事官方、实名记者采访、商店页 = 一手。评分输入里不给信源分级（现有设计，防止“看名气打分”），所以“一手”按材料内部证据判断；信源分级的门槛差另由 `selection.ts` 管。

### D4. 传闻标注

- 写作步骤（`content-understanding.md`、`summarize-article.md`、`summarize-long-post.md`）：材料核心是未经当事方确认的爆料时，`titleZh` 以“传闻：”开头，摘要首句写明“据 XX 爆料/报道”。
- 结构化（`structure.md`）：传闻的 fact 以爆料方为主体、动作写“爆料/称”，这样官方后来确认时，归组会把它当作同一事件的进展，而不是同一次发生。
- 标签：默认不加新标签（Q3-3）。

### D5. 日报结构（引擎补丁，最小化）

现状（`reports/edition.ts` + `compose.ts`）：前 12 条进正文（每源最多 2 条），第 1 条是头条（标题 + 整段摘要），第 2–4 条是“今日看点”，其余按类别分节，之后最多 10 条一行快讯。

改为：
1. **一句话头条**：`lead.leadParagraph` 只取摘要第一句（按“。！？”切）。
2. **3 条要闻**：保持现有 `highlights`（第 2–4 条）。
3. **分类速览配额**：`site/site.ts` 新增
   ```ts
   REPORTS.dailyLayout = { sectionQuotas: { "new-games": [2, 4], esports: [2, 4], industry: [3, 5] } }
   ```
   `arrangeDaily` 先满足各类下限（不够就少，不硬凑），再按重要性补到上限；超过上限的进快讯。不配置时行为与上游一致（便于合并上游）。
4. **明日关注**（Q3-4）：结构化新增可选字段 `upcoming: [{ date: "YYYY-MM-DD", what: "≤30字" }]`，只收原文明示的未来日期（上线、开测、赛事、版本、停服）。日报取近 7 天已公开资料中 `date` = 次日（北京时间）的事项，去重后最多 5 条，每条带来源链接。没有就不显示这一节。
5. **每条注明来源**：正文、要闻、速览、快讯、明日关注每条都带来源名和原文链接（现有条目已带 `sourceId`，前端补显示）。
6. **社区热议 1–2 条**：依赖热榜信号，在变更 4 做。

### D6. 门槛校准流程

1. 用户确认 `calibration-sample.json` 的 30 条预标注（select / reject / either，及预筛和类别）。
2. 变更 2 上线采集后，按信源和排除类型分层，再抽 70–170 条，凑到 100–200 条；`benchmarkSplit` 按 7:3 分开发集和留出集；`samplingStratum` 用排除类型（攻略、软文、传闻、折扣……）和类别。
3. 转成 `.data/gold.jsonl`（正文用文章页提取的正文，没有就用 RSS 摘要）。
4. 有 key 之后：
   ```bash
   node --env-file=.env scripts/eval-selection.ts --gold .data/gold.jsonl --split development --label "v0 占位提示词"
   # 改提示词后
   node --env-file=.env scripts/eval-selection.ts --gold .data/gold.jsonl --split development --label "v1 灵感标准"
   node --env-file=.env scripts/eval-selection.ts --gold .data/gold.jsonl --split holdout --label "v1 留出集"
   ```
   看准确率、查准率、查全率和 40–90 的门槛扫描；在后台 SelectBench 看错例。先改提示词再动门槛。
5. 预筛与类别：`eval-selection` 不评类别。用开发库跑完整流水线后，用 SQL 对比 `analyses.output->>'category'` 与标注；预筛对比 prefilter 结果。
6. 验收（Q3-6，建议）：开发集查准率 ≥ 0.80、查全率 ≥ 0.70；留出集不低于开发集 0.05 以上；排除类样本 0 条入选。

## Risks / Trade-offs

- 规则写成上限后模型可能整体偏严，精选太少 → 用门槛扫描看，必要时下调 T2 门槛，不回退规则。
- 传闻前缀依赖模型判断“是否已确认”，可能误标 → 校准样本里放 5–10 条传闻/确认对照。
- 日报配额：电竞量小的日子凑不到 2 条 → 不硬凑，下限是“尽量”。
- 明日关注依赖原文写明日期；多数新闻不写 → 这一节常常为空，属于预期。
- 引擎补丁和上游日报代码可能冲突 → 配置不设时保持上游行为；files.md 单列。
